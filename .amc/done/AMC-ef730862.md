# AMC-ef730862: Core LlmCall type, migration 003, and Repository.recordLlmCall

## What was built
Implemented the full scope of the ticket per spec (specs/feat-c990e0fd/001-core-llmcall-type-and-migration/spec.md):

- Added `LlmUsage`, `LlmMessage`, `LlmCall` interfaces to `packages/core/src/types.ts` (modeled exactly after `ToolCall` conventions).
- Extended `Commit` interface with `llmCall: LlmCall | null` (after `toolCall`).
- Extended `CommitInput` with `llmCall?: LlmCall | null`.

- Updated privacy contract comment in `packages/core/src/telemetry/reporter.ts` to document the new attr.
- Added comprehensive unit tests:
  - `packages/core/src/__tests__/llm-call.test.ts`: roundtrip via commit() + getCommit(), null handling, recordLlmCall auto-stamping, deterministic hash regression, error status.
  - `packages/core/src/__tests__/migrations-003.test.ts`: TARGET_VERSION===3, applies to v2 fixture, `SqliteIndex.init(path)` on v2 DB upgrades schema to v3 with llm_call column + migrationStatus.current===3, rowToCommit defensive null synthesis.
- Regenerated `packages/core/etc/agentgit-core.api.md` baseline via api:update so new public surface (`Llm*` types, `recordLlmCall`, `LlmCallInput`) is locked in.
- `pnpm --filter @agentgit/core api:check` and root `pnpm api:check` both exit 0.
