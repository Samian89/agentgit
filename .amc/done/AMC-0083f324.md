# AMC-0083f324 — CLI push/fetch/pull integration coverage

## What was built
Added `packages/cli/tests/integration/remote-sync.test.ts`, a new integration
test file that drives `pushCommand`, `fetchCommand`, and `pullCommand` against
an in-process `buildServer` from `@agentgit/remote-server` (the same harness
pattern used by `packages/remote-server/tests/roundtrip.test.ts`).

The suite contains five tests covering the gaps called out in
`specs/feat-ddd133e2/003-cli-untested-commands/spec.md`:

1. **Happy path** — push from repo A using a persisted `remotes.origin.token`,
   fetch into repo B using the `--token` flag (no persisted token), seed B's
   local session ref via `pullCommand`, advance A with a new commit, push it,
   then fast-forward B with another `pullCommand`. Asserts on both server-side
   storage (via `getStorage(app).listRefs()`) and local `refs/` state.
2. **`--token` override beats a wrong persisted token** — push succeeds when
   the explicit flag is supplied even though the stored token would 401.
3. **401 path** — bad persisted token produces a non-zero exit on both
   `pushCommand` and `fetchCommand`, and the error message reaches
   `console.error`.
4. **Non-fast-forward push (ref CAS conflict)** — divergent local session
   head (sibling commit) causes `pushCommand` to refuse with exit 1 and a
   `non-fast-forward` message. This is the user-visible analogue of the
   server's 409.
5. **Pull `--token` override + missing-token failure** — pull exits 1 when no
   token is reachable, and succeeds when one is passed via the override.

Result: `pnpm --filter @agentgit/cli test:integration` → 7 files, 42 tests
passing (5 new tests added). The previously untouched modules
`packages/cli/src/commands/{push,fetch,pull}.ts` are now exercised end-to-end.

## Files changed
- `packages/cli/tests/integration/remote-sync.test.ts` — **new** (276 lines).
  Spawns a Fastify-based remote-server on `127.0.0.1:0`, configures local
  `.agentgit/config.json` via `remoteAddCommand`, then invokes the three CLI
  command functions directly. Cleans up the server (`await app.close()`) and
  tmp dirs in `afterEach`; spies on `console.error` via `vi.spyOn` to assert
  on error output (vitest's stderr capture doesn't catch `console.error`
  through `process.stderr.write`).

No production code or other tests were modified.

## What downstream tickets may consume
- The in-process server harness (build + listen on `:0`, `getStorage(app)` for
  assertions, tmpdir lifecycle) is now duplicated between
  `packages/remote-server/tests/roundtrip.test.ts` and
  `packages/cli/tests/integration/remote-sync.test.ts`. If more CLI tests need
  the same harness, factoring it into a shared test helper would be the
  natural next step — but the spec explicitly scoped this ticket to the CLI
  integration suite and did not request a refactor.
- The `console.error`-via-`vi.spyOn` pattern is a reusable way for future CLI
  tests to assert on command error messages without leaking output to the
  test runner. Existing tests use ad-hoc `process.stdout.write` overrides
  (see `remote.test.ts`); this is a slightly cleaner approach if a future
  ticket wants to unify them.
- No new exported APIs, types, or interfaces — pure test addition.
