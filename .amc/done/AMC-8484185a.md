# AMC-8484185a — Wire ShareSessionModal into App.tsx toolbar

## What I built
Surfaced the already-implemented `ShareSessionModal` from the Tauri desktop app's toolbar so the remote push flow (`list_remotes` / `add_remote` / `push_session`) is reachable from the UI. Followed the existing state-flag + conditional-render pattern used by the New Session and Abandon modals in the same file.

- Imported `ShareSessionModal` in `App.tsx`.
- Added `shareModalOpen` boolean state.
- Added a "Share" toolbar button that renders next to the existing abandon "…" button and is only visible when a session is selected. It carries `data-testid="share-session-button"` for future test hooks.
- Rendered `<ShareSessionModal dbPath={dbPath} sessionId={selectedSession} onClose={…} />` at the bottom of the component tree, guarded by `shareModalOpen && selectedSession` so it cannot mount without a selected session id.
- The modal itself handles list/add remotes, push, clipboard copy of share URL, and toast/error state internally — no changes required there.

## Test environment fix (necessary side-fix)
The repo's UI test suite was failing on this runner because the parent shell exports `NODE_ENV=production`, which caused `@vitejs/plugin-react` to bundle React's production build for tests. React's prod build throws `act(...) is not supported in production builds of React.` from `@testing-library/react`, breaking all 16 RTL tests across 5 files.

Confirmed pre-existing by stashing my changes and re-running on plain `master` — same 16 failures, identical signatures.

Fix: one-line `process.env.NODE_ENV = "test";` at the top of `packages/ui/vitest.config.ts`, with a comment explaining why. After this, all 21 tests pass (5 files, 0 failures).

## Files changed
- `packages/ui/src/App.tsx` — Added `ShareSessionModal` import, `shareModalOpen` state, toolbar "Share" button (gated on `selectedSession`), and conditional render in the modal-tree section.
- `packages/ui/vitest.config.ts` — Forced `NODE_ENV=test` at config load so the React dev bundle is used regardless of the parent shell. Required to actually validate the wiring per acceptance criteria; pre-existing failure unrelated to the share wiring itself.

## Acceptance criteria
- [x] **Share button appears when a session is selected** — toolbar shows "Share" next to "…" only while `selectedSession` is truthy.
- [x] **Modal opens with correct `dbPath` / `sessionId`** — props plumbed from existing `dbPath` state and `selectedSession` id; rendered behind `shareModalOpen && selectedSession` guard.
- [x] **Modal can list / add remotes and call `pushSession`** — uses the already-implemented `ShareSessionModal` and the existing typed IPC wrappers in `packages/ui/src/ipc.ts`; Rust handlers `list_remotes` / `add_remote` / `push_session` already registered in `packages/ui/src-tauri/src/lib.rs`.
- [x] **UI test suite passes** — `cd packages/ui && pnpm pretest && pnpm test` → `Test Files 5 passed, Tests 21 passed`. `pnpm typecheck` also clean.

## APIs / types / interfaces other tickets may consume
- **Toolbar test hook:** the Share button carries `data-testid="share-session-button"`. Downstream UI/e2e tickets can target it to open the share flow without coupling to button text.
- **No new types, IPC, or exported symbols.** The share-side type surface (`RemoteRecord`, `PushSessionResult`, `listRemotes`, `addRemote`, `pushSession`) was already exported from `packages/ui/src/ipc.ts` in the previous spec and remains unchanged.
- **Pattern reference:** the modal wiring follows the same state-flag + bottom-of-tree conditional render used by `NewSessionModal` and `AbandonSessionModal`; future modals should mirror this shape rather than introducing alternatives.
- **Test env note for sibling tickets:** any new vitest-based UI test config in this repo should also pin `NODE_ENV=test` (or copy this config) to be robust to the parent shell's environment.
