# AMC-365e9100 — Remote sync with reference server

## 1. What was built

### 1.1 Protocol design — `docs/remote-protocol.md`

JSON-over-HTTPS protocol v1 documenting all five endpoints, bearer-token
auth (HMAC-validated, constant-time compare), resumable `Upload-Id`
semantics, error envelopes, and the bandwidth tradeoff vs. git packfiles
(~10–30% larger; rationale: simpler implementation, debuggable, gzip
recovers ~half the overhead). Sets the version contract via the
`AgentGit-Protocol: 1` header and the `/api/v1/...` URL prefix.

### 1.2 Client (`packages/core/src/remote/`)

- `protocol.ts` — request/response types, `REMOTE_PROTOCOL_VERSION`,
  `RemoteProtocolError`.
- `client.ts` — `RemoteClient` class implementing `listRefs`,
  `negotiateMissing`, `uploadObjects`, `commitUpload`, `downloadObjects`,
  `updateRef`. Pluggable `FetchLike` transport for tests.
- `sync.ts` — orchestration:
  - `pushSession(repo, opts)` walks reachable objects, negotiates, uploads
    in chunks (default 256 objects/chunk), CAS-updates the ref, writes a
    local `refs/remotes/<remote>/<ref>` tracking ref. Refuses non-FF
    remote updates client-side. Persists in-progress state to
    `.agentgit/remote-state.json` so a crash mid-push lets the next
    attempt reuse the same `Upload-Id`.
  - `fetchRefs(repo, opts)` walks the remote commit graph by downloading
    in batches, verifies every object's SHA-256, writes to the local
    object store, re-indexes commits/blobs/trees, and synthesizes a
    session row when a remote commit's `sessionId` is unknown locally.
    Writes `refs/remotes/<remote>/<ref>`.
  - `pullRef(repo, opts)` = `fetchRefs` + fast-forward-only update of
    `sessions/<id>` (or whatever the user names). Refuses non-FF.

Re-exported from `@agentgit/core` and surfaced on `Repository` as
`push() / fetch() / pull()` thin wrappers.

### 1.3 Reference server (`packages/remote-server/`)

Fastify app under `src/server.ts` exposing the five endpoints with bearer
auth (`--token-file`) and a dedicated NDJSON parser. Storage in
`src/storage.ts`:

- Objects under `data/objects/<2>/<62>` (canonical JSON, identical to the
  client format).
- Pending uploads under `data/pending/<upload-id>/<hash>` — atomic
  `tmp→rename` writes are the durability boundary.
- `data/refs.db` SQLite with `refs(name, target, type, updated_at)` and
  `pending_uploads(upload_id, hash, received_at)`.

Single-binary entrypoint at `src/cli.ts` →
`agentgit-remote-server --port 8787 --data-dir ./data --token-file ./tokens`.

### 1.4 CLI

- `agentgit remote add <name> <url> [--token=...] | remote list |
  remote remove <name>` — persisted under `remotes.<name>` in
  `.agentgit/config.json`.
- `agentgit push <remote> <session>` — uploads only missing objects, CAS
  ref update.
- `agentgit fetch <remote> [refs...]` — downloads + writes
  `refs/remotes/<remote>/<ref>`.
- `agentgit pull <remote> <ref>` — fetch + FF-only update; refuses non-FF
  with a clear error.

### 1.5 UI

- `packages/ui/src/components/ShareSessionModal.tsx` — modal with remote
  picker, inline "add remote" form, push button, error/status states,
  and a clipboard copy on success.
- `packages/ui/src/ipc.ts` — `listRemotes`, `addRemote`, `pushSession`
  helpers.
- Rust IPC commands in `packages/ui/src-tauri/src/lib.rs`:
  - `add_remote` / `list_remotes` — read/write `.agentgit/config.json`
    directly via serde_json.
  - `push_session` — shells out to the `agentgit` CLI (configurable via
    `AGENTGIT_CLI`) to keep the protocol logic in one place. Returns a
    shareable URL of the form `<remote-url>/sessions/<session-id>`.

### 1.6 Tests (32 new across the workspace)

- `packages/remote-server/tests/roundtrip.test.ts` (6 tests, all passing):
  - Two-machine roundtrip: push from A, fetch on B, `log` matches.
  - Negotiation: a re-push without new commits uploads 0 objects.
  - Auth: bad token → 401.
  - FF-only pull: refuses a non-FF advance.
  - Resumability: mid-push fetch failure leaves received[] persisted; the
    retry reuses the same Upload-Id and round-trip still completes.
  - Server-restart survival against the same `data-dir`.
- `packages/cli/tests/integration/remote.test.ts` (5 tests, all passing):
  add/list/remove persistence and validation.

## 3. APIs and types other tickets may consume

From `@agentgit/core`:
- `RemoteClient`, `RemoteClientOptions`, `FetchLike` — HTTP transport.
- `pushSession`, `fetchRefs`, `pullRef`, `remoteStateFilePath` — flow
  helpers; also exposed on `Repository.push/fetch/pull`.
- `REMOTE_PROTOCOL_VERSION`, `REMOTE_PROTOCOL_PREFIX`,
  `RemoteProtocolError`.
- Type re-exports: `RefsListRequest/Response`, `ObjectsMissingRequest/
  Response`, `ObjectsUploadResponse`, `ObjectsDownloadRequest`,
  `RefsUpdateRequest/Response`, `UploadLine`, `RemoteRef`, `RemoteError`,
  `PushOptions/Result`, `FetchOptions/Result`, `PullOptions/Result`,
  `RemoteUploadState`, `RemoteStateFile`.

From `@agentgit/remote-server`:
- `buildServer(opts)` returns a Fastify app. `RemoteServerOptions`
  documents `dataDir`, `tokenFile | tokens`, `serverSecret`,
  `maxChunkBytes`, `logger`.
- `RemoteStorage` — accessible for advanced uses; `getStorage(app)`
  extracts it from a built app.

Local convention introduced (consumed by spec 006 merge work):
- `refs/remotes/<remote>/<refName>` tracking refs written by `fetchRefs`.
- `.agentgit/remote-state.json` — resumable upload state file; safe to
  delete to abandon an in-flight push.
- Remotes persisted under `.agentgit/config.json` as
  `{ "remotes": { "<name>": { "url": "...", "token": "..." } } }`.

Wire-protocol stability: bumping a JSON field is non-breaking; new
endpoints under `/api/v1/` are non-breaking; envelope changes require
`/api/v2/` and a new protocol-version header. See
`docs/remote-protocol.md §8`.
