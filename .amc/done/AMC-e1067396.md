# AMC-e1067396 — Establish test infrastructure for web-viewer package

## Cycle 3 — real fixes found and applied

The previous two reviewer rejections both surfaced the same root cause: the **tester runner** itself could not authenticate (`HTTP 401 Unauthorized` from `chatgpt.com/backend-api/codex/responses`, "Failed to refresh token: refresh token was already used"). That is an environment problem in the tester runner, not a code problem in this branch. However, while re-verifying the work this cycle I found **two real defects** that the rejected runs masked. Both are fixed in this cycle.

### Real bugs fixed this cycle

1. **`pnpm-lock.yaml` was out of sync with `packages/web-viewer/package.json`.** The package.json declared `@testing-library/react`, `@testing-library/user-event`, `@testing-library/jest-dom`, `happy-dom`, and `vitest` as devDependencies, but the lockfile still listed only the original runtime deps. CI uses `pnpm install --frozen-lockfile`, which would have failed with:

   ```
   ERR_PNPM_OUTDATED_LOCKFILE  Cannot install with "frozen-lockfile"
   because pnpm-lock.yaml is not up to date with packages/web-viewer/package.json
   ```

   Regenerated by running `pnpm install --no-frozen-lockfile`. The updated lockfile is now committed and `pnpm install --frozen-lockfile` succeeds (verified locally: "Lockfile is up to date, resolution step is skipped").

2. **`@testing-library/react` was not actually linked into `packages/web-viewer/node_modules/`** before the lockfile fix, so any test that imported from it (such as the new App.test.tsx — see next section) failed at the Vite import-analysis stage:

   ```
   Error: Failed to resolve import "@testing-library/react" from "src/App.test.tsx"
   ```

   The lockfile regeneration above is what made pnpm symlink the testing-library packages into web-viewer's node_modules.

### New deliverable this cycle

3. **`packages/web-viewer/src/App.test.tsx`** — added the optional drop-zone smoke test the spec calls out as a follow-up. 2 tests:
   - Renders `<App />` (idle state) and asserts the documented `data-testid="drop-zone"` is in the DOM with the right class and without the `active` modifier.
   - Asserts the "AgentGit Web Viewer" heading, the "Read-only" disclaimer, and the "Drop a …" prompt are all visible in the idle state.

   The test `beforeEach` resets `window.history` to `/` so a sibling test that mutates `?bundle=…` cannot make the auto-load `useEffect` fire and shift `App` out of the idle state.

## APIs / types / interfaces other tickets may consume

None. This ticket is test-only and adds no exports. The behaviourally-visible effects for sibling tickets are:

- `pnpm test` at the repo root now runs web-viewer tests as part of the workspace — anyone touching `packages/web-viewer/src/bundle/unpack.ts` or `packages/web-viewer/src/in-memory-index.ts` (or `App.tsx`'s idle state) sees test failures locally without remembering the per-package `--filter` invocation.
- CI's `pnpm install --frozen-lockfile` now actually installs web-viewer's testing devDependencies. If a future ticket adds more devDeps to web-viewer, they must remember to commit the regenerated lockfile.

The `buildBundle()` helper in `unpack.test.ts` remains test-private. If a future ticket needs a shared bundle-fixture builder it should be lifted into `packages/web-viewer/test/` then.
