# AMC-e1067396 — Establish test infrastructure for web-viewer package

## Cycle 5 — added direct coverage for `hash.ts`

### Why this cycle exists
Reviews 1–4 all rejected with the same trailer: `tester run did not emit a parseable TESTER_VERDICT trailer`, rooted in the tester runner's own auth failure (`HTTP 401 Unauthorized` from `chatgpt.com/backend-api/codex/responses`, "Failed to refresh token: refresh token was already used"). Nothing in this branch will fix a refresh-token problem inside the tester runner itself. Each builder cycle has therefore been used to harden the deliverable so when the tester does come back online there is the least possible surface to fault.

### Change this cycle
- **`packages/web-viewer/src/bundle/hash.test.ts`** — 13 new tests for the lowest-level bundle primitive (`canonicalJson` + `sha256`). Until now `hash.ts` was exercised only indirectly through `readBundle`'s object-hash verification step. Direct tests make canonicalisation and the non-content-field stripping rules explicit and catch regressions before they manifest as cryptic "object X failed hash verification" errors in `unpack.test.ts`.

  Covered:
  - `canonicalJson` — top-level key sort, nested-object key sort, array order preservation, key sort inside objects nested in arrays, primitive passthrough (`null`, number, string, boolean), determinism across permutations of the same logical object.
  - `sha256` — output is 64 lowercase hex chars, canonicalisation (key order doesn't affect digest), top-level `hash` / `signature` / `publicKey` stripping (all three fields verified against the same baseline digest), nested `hash` fields are **not** stripped (mirrors `packages/core/src/hash.ts` semantics — content fields nested inside child objects are part of the content), content-field changes do produce different digests, arrays do not get field-stripping applied, empty `{}` hashes deterministically.

## APIs / types / interfaces other tickets may consume

None. This ticket is test-only and adds no exports. Behaviourally-visible effects for sibling tickets:

- **`pnpm test` at the repo root now runs web-viewer tests** as part of the workspace. Anyone touching `packages/web-viewer/src/bundle/{hash,unpack}.ts`, `src/in-memory-index.ts`, or `App.tsx`'s idle state sees test failures locally without remembering the per-package `--filter` form.
- **CI's `pnpm install --frozen-lockfile` now actually installs web-viewer's testing devDependencies** — if a future ticket adds more devDeps to web-viewer, they must commit the regenerated lockfile.
- **CI's `unit` job has an explicit web-viewer step** — failures will surface there in addition to the root `pnpm test` step.
- **The `hash.ts` semantics are now pinned by tests**: top-level non-content-field stripping (`hash` / `signature` / `publicKey`) applies only at the outermost object, arrays preserve order, primitives pass through. Future tickets that adjust `hash.ts` will see those tests fail if the rules drift away from `packages/core/src/hash.ts`.

The `buildBundle()` helper inside `unpack.test.ts` remains test-private. If a future ticket needs a shared bundle-fixture builder, it should be lifted into `packages/web-viewer/test/` at that point.
