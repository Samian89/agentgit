# AMC-e1067396 — Establish test infrastructure for web-viewer package

## Cycle 4 — explicit CI step for web-viewer

### Why this cycle exists
Reviews 1–3 all rejected with the same trailer: `tester run did not emit a parseable TESTER_VERDICT trailer`. Looking at the embedded tester output, the root cause is upstream of this branch: the tester runner can't authenticate (`HTTP 401 Unauthorized` from `chatgpt.com/backend-api/codex/responses`, "Failed to refresh token: refresh token was already used"). Nothing in this branch will fix a refresh-token problem inside the tester runner. I have, however, used each cycle to harden the deliverable so a future passing tester run has the least possible surface to fault.

### Change this cycle
- **`.github/workflows/ci.yml`** — added an explicit `pnpm --filter @agentgit/web-viewer test` step immediately after the existing `pnpm test` in the `unit` job. This directly addresses spec item #6 ("Update the root CI 'unit' job ... to run `pnpm --filter @agentgit/web-viewer test`"). The step is technically redundant on a green run because `pnpm test` already includes the web-viewer project via `vitest.workspace.ts`. The value of having it explicit:
  - **Single-package failure signal in CI logs.** If the web-viewer tests break, the GitHub Actions step name is "Run pnpm --filter @agentgit/web-viewer test" and the reviewer doesn't have to grep the workspace output for `|@agentgit/web-viewer|`.
  - **Single-package retry target.** A flaky run can be re-attempted on this step alone.
  - **Discoverability.** Future contributors reading `ci.yml` see web-viewer's tests are wired up explicitly.

## APIs / types / interfaces other tickets may consume

None. This ticket is test-only and adds no exports. Behaviourally-visible effects for sibling tickets:

- **`pnpm test` at the repo root now runs web-viewer tests as part of the workspace.** Anyone touching `packages/web-viewer/src/bundle/unpack.ts`, `src/in-memory-index.ts`, or `App.tsx`'s idle state sees test failures locally without remembering the per-package `--filter` form.
- **CI's `pnpm install --frozen-lockfile` now actually installs web-viewer's testing devDependencies.** If a future ticket adds more devDeps to web-viewer, they must commit the regenerated lockfile.
- **CI's `unit` job has an explicit web-viewer step** — failures will surface there in addition to the root `pnpm test` step.

The `buildBundle()` helper inside `unpack.test.ts` remains test-private. If a future ticket needs a shared bundle-fixture builder, it should be lifted into `packages/web-viewer/test/` at that point.
