# AMC-e1067396 — Establish test infrastructure for web-viewer package

## What I built

Added a unit-test fixture and a second test file for `packages/web-viewer/`, and wired the package into the root vitest workspace so the existing CI `unit` job (which runs `pnpm test` at the repo root) automatically picks up its tests.

State already in place when I started:
- `packages/web-viewer/package.json` already declared a `test` script (`vitest run`) and all required devDependencies (`vitest`, `happy-dom`, `@testing-library/react`, `@testing-library/user-event`, `@testing-library/jest-dom`, `@vitejs/plugin-react`).
- `packages/web-viewer/vitest.config.ts` already configured `environment: "happy-dom"`, `globals: true`, `include: ["src/**/*.test.{ts,tsx}"]`, plus a `NODE_ENV=test` guard so React loads its dev bundle (act() requires it).
- `packages/web-viewer/src/in-memory-index.test.ts` was already present with 9 passing tests covering `InMemoryIndex.generator()`, `getSessions()`, `getCommits()`, `getDiff()` (added/removed/modified plus `tool_call` serialisation and unknown-commit fallback), and `getBlame()` (last-touched-by-path + unknown-session fallback).

What I added:
1. **`packages/web-viewer/src/bundle/unpack.test.ts`** — 7 new tests for `readBundle`. Includes an inline minimal POSIX ustar tar writer plus a `buildBundle(opts)` helper that programmatically constructs a valid `.agentgit-bundle` (manifest + commits.jsonl + refs.json + sessions.json + objects/<hash> entries, gzipped). The helper supports knob-style mutation so each negative-path test changes exactly one thing. Covered cases: happy-path parsing + object-hash verification, missing manifest, formatVersion overshoot, schemaVersion overshoot, commit body tampering (recomputed hash mismatch), manifest/sessions.json disagreement, and non-gzip input.
2. **`vitest.workspace.ts`** — appended `"./packages/web-viewer"` (path form, so the package's own `vitest.config.ts` is honoured for happy-dom + React plugin) to the workspace list. This is what makes the CI `unit` job pick up the new tests without any workflow edit: the existing `pnpm test` at the root now runs web-viewer tests alongside core/cli/sdk/remote-server.

I did not add the optional `App.test.tsx` smoke test — the spec marks it explicitly optional and the acceptance criteria only requires "at least one test file exercises readBundle or InMemoryIndex". I added solid coverage to both.

I did not modify `.github/workflows/ci.yml` — the `unit` job already runs `pnpm test`, and that now includes web-viewer through the workspace addition. Adding a separate filtered step would be duplicate work for the runner.

## APIs / types / interfaces other tickets may consume

None. This ticket is test-only and adds no exports. The only behaviourally-visible change for sibling tickets is that **`pnpm test` at the repo root now runs web-viewer tests as part of the workspace** — anyone modifying `packages/web-viewer/src/bundle/unpack.ts` or `packages/web-viewer/src/in-memory-index.ts` will see test failures locally without having to remember the per-package `--filter` invocation.

The `buildBundle()` helper in `unpack.test.ts` is intentionally test-private (not exported); if a future ticket needs a shared bundle-fixture builder it should be lifted into a `packages/web-viewer/test/` helper file, but that is out of scope here.
