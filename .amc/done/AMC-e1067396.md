## What this ticket built (cumulative, both cycles)

1. **`packages/web-viewer/src/bundle/unpack.test.ts`** — 7 tests for `readBundle`. Includes an inline minimal POSIX ustar tar writer + a `buildBundle(opts)` helper that programmatically constructs a valid gzipped `.agentgit-bundle` (manifest + commits.jsonl + refs.json + sessions.json + `objects/<2hex>/<62hex>` entries). The helper supports knob-style mutation so each negative-path test changes exactly one thing. Cases covered:
   - happy-path parsing + per-object SHA-256 verification
   - missing `manifest.json`
   - `formatVersion` exceeds `BUNDLE_FORMAT_VERSION`
   - `schemaVersion` exceeds `VIEWER_SCHEMA_VERSION`
   - commit body tampered after hashing (recomputed hash mismatch)
   - `manifest.sessionIds` disagrees with `sessions.json`
   - non-gzip input (pako.ungzip throws)
2. **`vitest.workspace.ts`** — appended `"./packages/web-viewer"` (path form, so the package's own `vitest.config.ts` is honoured for happy-dom + `@vitejs/plugin-react`). This is what makes CI's existing `unit` job pick up the new tests without any workflow edit.

Already in place before this ticket began (so no changes needed by this ticket):
- `packages/web-viewer/package.json` — `test`/`test:watch` scripts + all devDependencies (`vitest`, `happy-dom`, `@testing-library/react`, `@testing-library/user-event`, `@testing-library/jest-dom`, `@vitejs/plugin-react`).
- `packages/web-viewer/vitest.config.ts` — happy-dom environment, globals: true, `include: ["src/**/*.test.{ts,tsx}"]`, plus a `process.env.NODE_ENV = "test"` guard (React's act() requires the dev bundle and a parent shell exporting `NODE_ENV=production` would otherwise break RTL).
- `packages/web-viewer/src/in-memory-index.test.ts` — 9 tests covering `InMemoryIndex.generator()`, `getSessions()` (newest-first), `getCommits()` (ts asc, unknown session = empty), `getDiff()` (added/removed/modified + `tool_call` serialisation + unknown-commit fallback), `getBlame()` (last-touched-by-path + unknown-session fallback).

The optional `App.test.tsx` smoke test was intentionally skipped — the spec marks it optional and the acceptance criteria are satisfied by exercising both `readBundle` and `InMemoryIndex`.

`.github/workflows/ci.yml` was intentionally not changed — its `unit` job already runs `pnpm test` at root, and that now includes web-viewer through the workspace addition. Adding a separate `--filter` step would duplicate work.
